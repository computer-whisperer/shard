Clause by clause:

- **An ordinary E library contributing an I-producing tactic through the fixed interface** —
  `v3/examples/tactic/bool_split.shard`: `(fn solve ((goal (List Int)) (hints (List Int))) (List
  Int))` over the kernel's S reader, loaded `RUNNABLE … route=e_first` as any E module; the
  interface is data at the boundary, `(goal ((a Bool) (b Bool)) (= (Bool.and a b) (Bool.and b a))
  (applicable rfl rw cases induction wf decide exact apply have show unfold reduce simp_only
  sorry))` in, `((cases a ((false () (cases b ((false () (decide)) (true () (decide))))) (true ()
  …))))` out; the library sees no `El`, no `Expr`, no environment.
- **Its evidence checked through the same path as built-in tooling** — the answer is replayed
  through `tac_prove` before `RDSolved`, as a hand-written block and the engine's are; the sidecar
  entry it writes is `(proof-for NAME FP (by STEP…))`, indistinguishable at the pin (`auto_tactic`:
  the entry replays with the library imported and never run; the delegation is unread by the
  build, as the hints are). A refused answer is the library author's feedback: `tactic=M.FN:
  decide_failed: step 1: the decision does not evaluate to true: (= n n) — the goal: (n : Nat) ⊢ (=
  n n)` (measured on a probe).
- **A proposed grammar extension receives the documented refusal** — `notation` and its kin are
  `lean_form` with the pointer naming the library route (pin `lean_notation`); an unknown step is
  `unknown_step` with I's roster and the same pointer (pin `by_unknown_step`); `(tactic …)` inside a
  hand-written `by` is `unknown_step` (measured on a probe); `docs/LEAN.md`'s row for a tactic
  extension.
- **Replay unchanged under changed ambient simp and instance settings** — an entry carries its
  rules (`simp_only RULE…`, `arith only FACT…`), there is no ambient simp set and Init's instances
  are closed by the export (slice 3.27 rule 3's table); the hints are the producer's and unread at
  replay: pin `auto_hints_changed` (an entry written under `(induct n)` replays with the source
  saying `(budget 1)`) and the entrypoint's hints-changed copy (the delegation with `(budget 1)`
  added replays its six theorems).
- **A dependent motive** — pin `by_cases_dependent`: under `cases` and `induction` every local
  whose type mentions the eliminated local is reverted into the motive and re-introduced in each
  arm after the fields, so the zero arm of `(n : Nat) (h : (< 0 n)) ⊢ (<= 1 n)` faces `h : (< 0
  Nat.zero)` and `(arith h)` refutes it (before the slice the arm faced `h : (< 0 n)` and could not
  close — the gap measured on 2026-10-12 before the design); calc's 100 claims replay unchanged
  under the revert (`tactic_test`).
- **Reused local names in sibling branches** — pin `by_sibling_names`: two arms naming the same
  field and the same `have`, each filling closing over its own locals; held before the landing,
  nothing built (an arm opens fresh locals, display names are the binders').
- **A guarded occurrence whose source changed** — pin `by_rw_occ_guard`: `(rw Nat.add_zero (occ 1
  (+ a 0)))` rewrites the expected instance in `ok`; the same block over `moved`, whose terms
  swapped, is refused `rw_occ_changed: … the occurrence found is (+ b 0), not the expected (+ a 0)
  — the source moved under the guard`.
- **An external P accepted through `exact`** — pin `by_exact_external`: Init's `Nat.le_refl`,
  `Nat.add_comm`, `Nat.le_succ` applied (Lean's P through the export); the library builds `(exact
  (Nat.le_refl n))` and `(exact (Eq.refl n))` as text for `le_self` and `eq_self`, accepted through
  the one check.
- **An I schema upgrade separate from a foundation change** — the sidecar's first form `(sidecar
  N)`, 2 from this slice; pin `auto_schema_old` (slice 3.22's sidecar, no form, replays and is
  reported `SIDECAR main.shard schema=1 current=2`), pin `auto_schema_future` (`(sidecar 3)` is the
  load error `sidecar_schema`), the entrypoint's schema-1 copy (reported, six theorems accepted);
  the export and K unchanged by the upgrade — law §7.2's four versions kept apart (K's rules, I's
  schema, P's encoding, the producer's implementation in the sidecar's comment).
- **One engine's solution checked identically by another** — the entrypoint: the engine solves
  `use_split`'s six statements in a second copy delegated `auto`; the two sidecars differ
  (`le_self` by `(arith only (farkas 1))` against `(exact (Nat.le_refl n))`, `and_comm` by nested
  inductions against nested `cases`), both replay to the same six `ACCEPT` records but for the
  axiom closure — the `hash` field is the statement's fingerprint; the closure is the proof's, and
  the engine's `le_self` by `arith` rests on `propext` and `Quot.sound` where the library's `(exact
  (Nat.le_refl n))` rests on nothing, which the gate checks as such —, both are stored by
  `load.shard --store` and verified by `verify_release` (K, the host and the JSON reader, no
  elaborator, no producer), the same number of declarations accepted in each.
- **The risk, an IR only its producer can read** — measured on the artifact: the library's sidecar
  is replayed by `load.shard` with the library never run (no `PROVED`, no `TACTIC` record), and
  the engine's and the library's entries are read by the same reader to the same acceptance.
