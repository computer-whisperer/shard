## 3. Documentation gaps (the measurement's product)

1. **A zero-parameter `fn` has two spellings by route, and neither document says so.** On the
   typed route a bare `f` in argument position is accepted (`std/list.shard` line 151,
   `sorted_demo`, `DEFINE`d on every load above); on the E-first route (a body that calls an
   extern — every `main`) the same spelling is `REFUSE … function_value: … in argument
   position (law §4.3)`, and `(f)` is required. LEAN.md list 2's `function_value` row names
   lambdas, `f ∘ g`, `List.map f` and partial application only; LANGUAGE.md §5.4/§6.7 say "a
   function name in argument position is the escape rule's refusal" without excepting a
   constant of arity zero on the typed route. The refusal message has no pointer (LEAN.md list
   3's last row promises one for each).
2. **LEAN.md list 2 does not say which refusals end the file.** `lean_form` arrived as
   `READ-ERROR FILE lean_form: …` (the file stops at its first — a second form in the same
   file would never be read), `inhabited_default` as `REFUSE NAME …` (the file continues).
   The table's header says "the record's reason is in the second column" and nothing about
   the record kind; an author batching several Lean forms into one file to see all the
   refusals would see only the first.
3. **The `inhabited_default` pointer names a constant this pin does not have.** The message
   says "write `List.get?` for an Option"; `v3/std/migration.shard`'s header and LEAN.md list
